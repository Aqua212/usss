# USSS · Памятка Memphis

Статический сайт для GitHub Pages. Фреймворки и сборка не нужны.

## Публикация

1. Создайте репозиторий на GitHub, например `usss-memphis`.
2. Загрузите **содержимое** этой папки в корень репозитория (не саму папку): `index.html`, `styles.css`, `app.js`, `laws.json`, `questions.json`, `README.md`.
3. На GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**. Выберите ветку `main`, папку `/ (root)` и сохраните.
4. После публикации ссылка появится в Settings → Pages. Обычно это `https://USERNAME.github.io/REPO/`.
5. В `app.js` замените `USERNAME` и `REPO` в `REMOTE_LAWS_URL` на свои значения, например `https://raw.githubusercontent.com/example/usss-memphis/main/laws.json`. Пока адрес не настроен, кнопка обновления читает размещённый рядом `laws.json`.

Сначала публикация или обновление GitHub Pages может занять несколько минут. Если сайт не загрузился, убедитесь, что `index.html` лежит в корне выбранной ветки и проект публичный, либо настройки вашей учётной записи поддерживают Pages для приватных репозиториев.

## Структура базы `laws.json`

- `schemaVersion`: номер формата, сейчас `1`.
- `updatedAt`: дата законодательной базы в формате `ГГГГ-ММ-ДД`.
- `quizReviewedAt`: справочная дата последней проверки тренажёра.
- `sources`: массив объектов `{ "name", "url" }` с HTTPS-ссылками.
- `cards`: массив объектов `{ "group", "title", "body", "ref", "cat" }`; допустимые категории: `Контакт и охрана`, `Задержание`, `Обыск и доказательства`.
- `codes`: массив из объектов с `id: "pc"` и `id: "usss"`, названием `title` и массивом `articles`. Каждая статья: `{ "title": "Статья 17", "text": "полный текст статьи..." }`.

Текст в JSON редактируйте через интерфейс GitHub или текстовый редактор, сохраняя корректный JSON и переводы строк как `\n`. После коммита нажмите на сайте «Обновить базу». Пока база вопросов не проверена по обновлённым законам, не меняйте дату `reviewedAt` в `questions.json`: сайт покажет предупреждение. Обновление базы не обновляет вопросы автоматически. Карточки с разъяснениями тоже необходимо пересматривать вручную при изменении норм.

Избранное привязано к позиции карточки/статьи в массиве; при перестановке или удалении элементов старые закладки могут указывать на другой материал. Для стабильности добавляйте новые элементы в конец, не переупорядочивая существующие.

## Вопросы

`questions.json` содержит `reviewedAt` и массив `questions`. Каждый вопрос имеет уникальный `id`, `topic`, тип `kind` (`one`, `multiple`, `tf`, `situation`, `article`), текст `prompt`, массив `choices`, массив индексов правильных ответов `correct` (с нуля), пояснение `explanation` и ссылку на норму `ref`. Варианты перемешиваются на сайте; индексы в файле указываются для исходного порядка. Все текущие вопросы ссылаются на ПК.

Всего 111 вопросов: 10 практических и 101 на определение статьи по заголовку. Это учебный материал, не официальная аттестация. После каждой правки законодательства требуется вручную проверить и обновить ответы, номера и пояснения.

## Локальный запуск

Открытие `index.html` двойным щелчком может заблокировать загрузку JSON браузером. В папке проекта выполните `python -m http.server 8000` и откройте `http://localhost:8000`. На GitHub Pages это не требуется.

Данные избранного, тренировочной сессии и обновлённой базы сохраняются в localStorage текущего браузера. Если хранилище переполнено или заблокировано, сайт сообщит об этом; обновлённая база в таком случае действует только до перезагрузки. Данные не синхронизируются между устройствами.
